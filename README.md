# pi5-lidar-bench

Бенчмарк із бонусного завдання звіту «Лідарна навігація на Raspberry Pi 5». Це KISS-ICP-подібна лідарна одометрія (C++17, один потік) у синтетичному лісі під Livox Mid-360: 400 дерев на гектар, крони з листям, кущі, вібрації.

У звіті я міряв час на скан на x86-сервері і перераховував на Pi 5 з коефіцієнтом 1,6-2,5, який оцінив сам. Цей запуск міряє той самий код на справжньому Pi 5 і замінює оцінку реальною цифрою. Заодно щосекунди пише навантаження ядер, пам'ять, температуру, частоту і тротлінг.

## Що потрібно

- Raspberry Pi 5 з 64-бітною Raspberry Pi OS. Для швидкого набору вистачить 1 ГБ ОЗП, для повного краще 2 ГБ і більше (довгі прогони тримають у пам'яті ~300 МБ).
- g++ і python3, бажано tmux:
  ```bash
  sudo apt update && sudo apt install -y g++ python3 tmux
  ```
- Інтернет під час запуску не потрібен.
- Запишіть, яке стоїть охолодження (активний кулер, радіатор, нічого). Від цього залежить тротлінг.

## Як закинути на малинку

З вашого комп'ютера:

```bash
scp pi5-lidar-bench.tar.gz <user>@<ip-малинки>:~
ssh <user>@<ip-малинки>
tar xzf pi5-lidar-bench.tar.gz && cd pi5-lidar-bench
```

## Запуск

```bash
tmux new -s bench                              # щоб прогін не обірвався, якщо відпаде ssh
COOLING="активний кулер" ./run.sh              # швидкий набір: 4 конфігурації, ~6-10 хв
COOLING="активний кулер" ./run.sh full         # усе зі звіту: 11 конфігурацій, ~30-40 хв
```

Якщо ssh відпав, підключіться знову і виконайте `tmux attach -t bench`. Зупинити прогін можна через Ctrl+C.

Скрипт сам збирає програму, записує інформацію про систему і запускає конфігурації по черзі.

## Що видно в терміналі

Поки йде бенчмарк, щосекунди з'являється рядок такого вигляду:

```
[   42 с] скан   37/120  ост.10:    212 мс/скан | процес 1.00 ядра    58 МБ | ядра   2%   1%   3% 100% | 63.4°C 2400 МГц | тротлінг: ні
```

- `скан 37/120`: прогрес; на початку кожної конфігурації замість нього стоїть «генерація сцени».
- `ост.10`: середній час обробки останніх 10 сканів. Жовтим підсвічується, якщо більше 100 мс, тобто на одному ядрі метод не встигає за лідаром 10 Гц.
- `процес`: скільки ядер займає бенчмарк і скільки пам'яті.
- `ядра`: завантаження кожного з чотирьох ядер. Бенчмарк прив'язаний до ядра 3, тож там має бути ~100%, а на решті майже нуль.
- Температура і частота: червоним, якщо від 80 °C. Нормальна частота під навантаженням 2400 МГц.
- `тротлінг`: розшифровка `vcgencmd get_throttled`. «ТРОТЛІНГ», «ЧАСТОТУ ОБМЕЖЕНО» або «НИЗЬКА НАПРУГА» означають, що результат занижений.

Після кожної конфігурації друкується її `ms_per_scan` і `drift_pct`, а наприкінці підсумкова таблиця.

## Що надіслати після «ГОТОВО»

Наприкінці скрипт друкує рамку «ГОТОВО» і під нею готовий текст. Надіслати треба дві речі:

1. Архів `results/pi5_lidar_<ім'я-малинки>_<дата>.tar.gz`. Забрати його на свій комп'ютер можна командою, яку скрипт надрукує в рамці, наприклад:
   ```bash
   scp <user>@<ip-малинки>:~/pi5-lidar-bench/results/pi5_lidar_raspberrypi_20261126_1030.tar.gz .
   ```
2. Текст із `results/<та сама назва>/message.txt` (він же надрукований під рамкою). Там коротко: коефіцієнт Pi 5 / x86, мс на скан і ядра для трьох головних конфігурацій, температура і тротлінг.

## Як читати результат

- Ядра при 10 Гц = мс/скан × 10 / 1000. Бюджет у завданні 2 ядра (50% Pi 5).
- Якщо p95 (95-й перцентиль часу на скан) менший за 100 мс, метод встигає в реальному часі на одному ядрі.
- Колонка `Pi/x86` показує, у скільки разів Pi 5 довше обробляє той самий скан, ніж x86-сервер зі звіту. Це число замінює мою оцінку 1,6-2,5. Рахується лише для прогонів тієї самої довжини, що у звіті (120 або 600 сканів).
- Колонка «прогноз звіту» показує діапазон, який я передбачав для Pi 5.
- Дрейф від заліза не залежить, і для швидкого набору має бути близьким до звіту: 0,45 / 0,46 / 0,47 / 0,17%. Якщо він сильно інший, щось не так зі збіркою.
- Час між однаковими запусками коливається на 10-20%, тож коефіцієнт має сенс із такою точністю.

## Що всередині

| Файл | Для чого |
|---|---|
| `run.sh` | збірка, інформація про систему, запуск конфігурацій, підсумок, архів |
| `src/icp_bench.cpp` | симулятор лісу і лідара, одометрія, заміри; можна запускати й окремо (див. нижче) |
| `tools/monitor.py` | живий вивід навантаження в термінал і CSV з посекундними даними |
| `tools/summarize.py` | таблиця, `summary.md` і `message.txt` |
| `analysis/estimates.py` | паперові розрахунки навантаження з модулів 3-4 звіту (`python3 analysis/estimates.py`) |
| `analysis/map_memory.py` | пам'ять мапи 100×100 м і час передачі по каналу, модуль 6 (потрібен numpy) |

Що лежить у `results/<назва>/`: `sysinfo.txt` (модель, ОС, частоти, температура до і після), для кожної конфігурації `*.out` (підсумок програми), `*.scans.csv` (час і похибка кожного скану), `*.monitor.csv` (посекундне навантаження, температура, частота), `*.monitor.json` (піки), а також `summary.md` і `message.txt`.

Окремий запуск бенчмарка без скрипта:

```bash
g++ -O2 -std=c++17 src/icp_bench.cpp -o icp_bench
MAXPTS=5 ./icp_bench 20000 1.0 120 1 out.csv   # променів, воксель (м), сканів, seed, файл
```

Змінні середовища: `MAXPTS` (точок на воксель), `MOUNT_INV=1` (перевернутий лідар), `VIB_DEG=0` (без вібрацій), `NOCV=1` (прогноз «попередня поза» замість сталої швидкості).
